# Long ledger accuracy comparison

The primary comparison is the proposed verified action path against the public SDK with zero fixed wait followed by an explicit check of the same receipt. The co-baseline uses the public SDK's default wait. Each paired arm begins with the same document, instructions, delay schedule, UI layout and injected fault. Order is counterbalanced. No changes to the runtime are part of this benchmark.

On each OS, six shards schedule 68 distinct successful-case seeds each (408 paired comparisons), with the first 12 per shard also using the default co-baseline (72 comparisons). Each task performs eight dependent account updates including copying an earlier value, addition, revisiting records and retaining untouched records. Each successful workflow requires 24 native click, type and Return actions. Layout changes at every revision. Instructions use deterministic developer logic. Baseline and candidate see the same window-scoped, versioned receipt and committed document. Startup, fixture reset and the independent delayed grade are excluded from the timed part.

Each shard also schedules six fault cases and two intentionally weak-receipt challenges. The fault cases stop a write before commit, lose acknowledgement after commit, or show a pending write then roll back. A single dispatch and an unambiguous stop are required. The weak-receipt challenge accepts pending state as success and is evaluated separately. Case outcomes and raw elapsed time are logged even when a grade fails. A completed CI job means that the measurement finished.

The grader inspects the complete document, revision, ordered input and commit journal, duplicates, extra actions and untouched rows, 350 ms after the controller returns. A controller reporting success on an incorrect outcome counts as false completion. Count baseline-only and candidate-only passes for every paired seed. A clean synthetic result supports precision only within this generator and these runner environments. The one-sided bound on a candidate-only regression for zero such events in n independent paired draws is 1 − alpha^(1/n). Use alpha=.05/3 for three simultaneous OS-specific bounds. A roughly one-percentage-point bound under this assumption motivates the 408-seed sample; repeated use of one application and host images does not bound regressions in other applications.
