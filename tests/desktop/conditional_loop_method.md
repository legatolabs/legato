## Conditional execution during a changing native session

This demo tests a pattern available to a developer with an app-owned command surface. The application accepts a revision and one of three actions in a native text field and commits the route to SQLite only if the observed revision still matches. The controller can read one visible event at a time. It never receives future events or grading data. The app injects a change to both flags after the initial read and before the first submission at a seeded fifth of positions.

An English request selects among four developer-supplied policies with different handling of flag, urgency, and precedence. An unsupported request should stop with no writes. A locally hosted Qwen2.5-3B Q4 model chooses a single policy ID at temperature zero. The serial controller asks for that choice before each submission. The compiled controller asks the same question once and executes its chosen decision table on fresh state throughout. A typed caller supplies a policy ID directly. A fourth controller starts with the correct policy ID and disables the app's revision check as a negative control. Each seed and interference schedule is paired across all four controllers. Methods run in seeded random order.

A physical type and Return through Legato dispatch each command. Linux X11, Windows Win32 or macOS Accessibility reads the app-owned window title to verify the typed token. A separate reader checks the new app revision. A rejected stale command triggers a fresh read and a new decision. The timer starts at the ready request and ends after independently reopening the SQLite journal and checking every route, revision, order and count. A wrong successful completion, duplicate or missing write fails the task. Model download, startup and session creation are outside the timer.

Each operating system has 18 seeded requests, including two unsupported requests, at lengths 8, 24 and 48. A small policy vocabulary makes this a test of reusing a decision rule and handling concurrent changes. The compiled arm is also what a developer that cached the first serial decision could implement on this app. GUI drivers generally cannot make an arbitrary application's final writes conditional on a revision. That facility is provided by this fixture.
