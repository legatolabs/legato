The runtime for
agents that act.

Inference got fast. Sandboxes got fast. The loop between them didn't. We're building the runtime for computer-use agents and the RL that trains them.

work with us see the runtime in action →

Reinforcement learning has always gone where practice is cheap.

It got good at backgammon first, then Go, because a board game costs almost nothing to play again. A program can play itself all night, and by morning it has played more games than a person could in a lifetime.

Then it got good at math and code, because there an answer can be checked by another program. Reasoning models were given problems, a way to tell right from wrong, and a great deal of practice, and they kept getting better.

The next thing to learn is work. Work is harder in a very unglamorous way: it happens on computers, and computers are slow.

The boring bottleneck

Watch an agent do a task on a real machine. It clicks, then waits. A window opens, a page loads, a spreadsheet recalculates, and only then does it find out whether the click did what it meant. A game of Go never made anyone wait for a spinner.

So the limit on how fast agents learn to work sits in an odd place: in the machines. How many you can run at once, how quickly each one settles after an action, how cheaply you can rewind one to the moment before a mistake and try again. Whoever makes that cheap gets to train the best agents.

The scaling law for agents is a scaling law for environments.

Over the shoulder

Most of what a company knows is passed on the way trades used to be, by one person watching another. Nobody wrote down the workaround in the ERP, or why one tab of that spreadsheet must never be sorted. New hires pick it up over someone's shoulder, on a screen share.

A machine can watch over a shoulder too. Every day, a company performs its own expertise on screens, step by step, and almost none of it is kept. Recorded, kept private inside the company, and turned into places an agent can practice with the real outcome as the reward, that work becomes a curriculum no lab could assemble: the company's own know-how, taught back to it.

We think the most useful enterprise models will be trained this way. They'll learn the job the way everyone else at the company did.

What we're building

Both of these ideas run into the same wall. Every rollout an agent learns from has to happen on a machine, and the machine sets the pace. So that's where we've decided to work.

There's an old pattern here. When compiling a program took all night, programmers wrote carefully and tried few ideas. When it took seconds, they started experimenting, and software got better much faster. Research has always moved at the speed of its slowest loop.

Agent training is about to go through the same change. A faster runtime means more rollouts from the same machines, shorter experiments, and more ideas tried before lunch. Better agents waste fewer steps, so the next round of rollouts is cheaper still. Each turn of the loop pays for part of the next one.

Open that bottleneck, and agents get to scale the way the rest of computing has: exponentially.

The road to general agents runs through experience. Experience runs through machines.

And then, atoms

A robot is the same loop with the stakes raised: a camera where the screen was, motors where the mouse was, and much less patience for a slow step. It will learn the way agents on screens do, by acting, failing and trying again, and all of that experience has to be made by someone. We'd like the runtime that makes it cheap on screens to be the one robots use too.
