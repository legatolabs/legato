Computer-use agents are slow, and the model is usually not the reason.

Watch one work. It clicks, then sits idle until the screen catches up. It takes a screenshot, sends it off, and waits for an answer. It goes through five menus to do what one command would. Every step is a round trip between a model and a machine, and much of the time goes to the trip, not the thinking.

Models will keep getting faster. That only makes the rest of the trip matter more.

What we're building

Legato is the runtime for agents that use computers: the layer between a model and the machine it controls. It decides when the screen is ready, what the model needs to see, and the quickest way to get something done. That's a click when clicking is the only way, and a command or a script when there's something faster.

It works with any model, and runs wherever the work is: your own computer, a container, a cloud sandbox. It's open source, because the part of an agent that touches your machine should be something you can read, run and change.

Why speed is the product

A slow agent is something you watch. A fast one is something you hand work to and stop thinking about. That difference decides whether computer use stays a demo or becomes how work gets done, and most of it comes down to the runtime.

Why it matters for training

Agents get better at computer work by doing it: trying tasks, failing, and trying again. Every attempt runs on a real machine. The faster and cheaper each attempt is, the more of them you can run, and the better the agents get. The runtime that serves agents is also the one that trains them.

Legato Cloud

Some of the waiting can only go away when the model and the machine run side by side. Legato Cloud does that: managed runtimes where the model and the desktop sit together, and a run can be paused, resumed or forked instead of started over.
