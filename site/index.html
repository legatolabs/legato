agents that act.

Inference got fast. Sandboxes got fast. The loop between them didn't. We're building the runtime for computer-use agents and the RL that trains them.

work with us try it on your computer →

Give Claude a computer and a spreadsheet-to-slides task, and run it in Anthropic's reference loop. On our 24 office tasks it takes 97 seconds on average. For 45 of them it isn't thinking. It's waiting: the loop sleeps two seconds before every screenshot, in case the screen is still changing.

That's how most computer-use agents work. They sleep a fixed time after every action, send a full-size screenshot every turn, ask the model for one click at a time, and click through menus that one shell command would skip. The model gets blamed for being slow, but nearly half the time isn't the model's.

Coding agents show the same thing. Across 434,912 steps of real Claude Code and Codex sessions, the machine took more of the wall clock than the model did: 53% and 45% of step time. If generation got five times faster, the machine's share would be 85% and 80%.

Labs make models faster every few months. The other half is the machine, and that's the half we work on.

What Legato does

Legato is an open-source runtime for computer-use agents. It sits between a model and the computer it controls, and works with any model behind an OpenAI-compatible API: Claude, GPT, Qwen, or one on your own GPU.

It waits for the screen, not the clock. It acts as soon as the screen has settled, instead of sleeping a fixed time. Same model, same 24 tasks, run side by side: Claude finished in 0.68 times the reference loop's time, and passed 48 of 48 in both.

It takes the fastest route. The model can plan several steps per call, and use a shell, a script or AppleScript where they're quicker than clicking. The screen is for what nothing else can do. It fills an 81-cell DCF in Excel in 7.2 seconds with one model call and one script, and still gets all 81 cells right in 7 to 16 seconds when the prompt leaves the formulas out.

It works where your work is. On a Mac it works in one app's window in the background, so you can keep using the computer. It also runs in a Linux container, a cloud sandbox or one you bring, and coding agents get it as an MCP server.

Why speed is the point

At 90 seconds a task, computer use is a demo: you sit and watch it. At 7 seconds it's a tool: you hand the task off and keep working. Most of the gap between the two is waiting, and waiting can be engineered away.

It matters even more for training. Agents will learn to use computers the way models learned to code: by attempting tasks over and over and being scored. Every attempt runs on a real machine, so the attempts you can run per hour set the price of a better agent. A faster runtime makes training cheaper.

Legato Cloud

The open-source runtime can only save time on its side of the network. Legato Cloud runs the model and the desktop next to each other. The model keeps a run's history cached between steps, so a new screenshot prefills in 70 ms instead of 158 ms on a 7B model.

Next we're building forks from memory. A running desktop restores in 0.7 to 0.9 seconds, against 3.9 to 7.4 seconds to boot one and replay to the same point. A run that goes wrong at step 30 can then try again from step 29, instead of from the start.
